# Plan: 高质量随机系统（元数据采集 + 质量加权随机）

## Goal
- 默认 `GET /random` 在“不指定任何筛选参数”的情况下，更大概率返回高质量图片（收藏/浏览/评论更高 + 分辨率更高）。
- 通过 Pixiv App API `illust/detail` 补全并持久化“热度元数据”（收藏/浏览/评论）与 tags，形成可用于质量判断的数据底座。
- 管理后台可视化展示“热度元数据缺失覆盖率”，可一键创建补全任务，无需手工操作数据库/后台脚本。
- 在不引入新依赖服务（Redis/ES）的前提下，保持随机接口热路径只读 SQLite + 低延迟。

## Research Summary（联网调研结论）
- Pixiv App API 的 illust 对象包含（至少）以下字段：`total_bookmarks`、`total_view`、`total_comments`、`tags`、`width/height`、`x_restrict`、`illust_ai_type` 等，可用于判断图片热度与质量。
- 参考依据（非穷举）：
  - `pixivpy` 的 API 返回示例包含 `total_view` / `total_bookmarks` 等字段（结构与 App API 兼容）。
  - 开源 Pixiv App API 客户端（Go/TS）定义包含 `total_view/total_bookmarks/total_comments` 与 `tags` 等字段。
  - Pixiv 官方帮助中心说明存在“点赞”功能，但公开字段层面更稳定的是“收藏/浏览/评论”等数值；本项目以 `total_bookmarks` 为主要质量信号。

## Current Implementation（本地调查结论）
- 随机选择：
  - 当前 `/random` 依赖 `images.random_key` + 组合索引 `idx_images_filter` 做 O(logN) 级别的随机定位（`backend/app/db/random_pick.py`）。
  - 当前“随机”与“质量”无关：不会优先选收藏数高/分辨率高的图片。
- 元数据补全：
  - `hydrate_metadata` 使用 `https://app-api.pixiv.net/v1/illust/detail`，并持久化 geometry/r18/ai/user/title/created_at/tags 等字段（`backend/app/jobs/handlers/hydrate_metadata.py`）。
  - 已有热度字段（收藏/浏览/评论）落库与持久化基础（DB-0108），但：
    - 管理后台未显示“热度字段缺失覆盖率”
    - backfill criteria 未显式支持 `missing=popularity`
    - `/random?format=json` 未展示热度字段与质量打分信息

## Design（方案）

### 1) 元数据底座（Step 1）
- 将热度字段纳入“缺失统计/缺失筛选/补全任务”的统一机制：
  - Admin summary 增加 `counts.hydration.missing.popularity`
  - Admin images list 增加 `missing=popularity` + 展示 bookmark/view/comment
  - Hydration backfill 支持 `criteria.missing` 选择 `popularity`
- 目的：让用户能快速把“随机命中率/质量”与“元数据覆盖率”关联起来，并可一键补全。

### 2) 质量加权随机（Step 2）
- 采用 **Tournament Selection（最佳 N 选 1）** 的“近似加权随机”：
  - 每次随机请求从满足筛选条件的集合中抽取 `N` 张候选（复用现有 `random_key` 索引），再按质量评分选出分数最高的一张。
  - 好处：无需扫描全表、无需维护复杂权重索引，SQLite 下性能稳定；`N` 越大，越偏向高分图片。
- 质量评分（Quality Score）：
  - 主信号：`bookmark_count`（收藏数）
  - 辅信号：`view_count/comment_count`（浏览/评论）+ `width*height`（像素）
  - 使用 `log1p` 缩放避免极端值垄断，并对缺失字段按 0 处理（缺失会降低质量命中概率，从而促使补全）。
- 可配置：
  - `strategy=quality|random`（默认 quality）
  - `quality_samples=N`（默认 5，可通过后台 Settings 调整默认值）
- 输出可观测性：
  - `/random?format=json` 的 `debug` 增加 `quality_score`/`quality_samples` 等信息，便于解释“为什么这张图更常被抽中”。

## Scope
- In:
  - 后端：补全缺失统计扩展（popularity）、random 质量策略实现、runtime settings 支持随机策略默认值。
  - 前端：Hydration/Images/Playground/Settings 页面适配（可见热度字段、可配置默认策略、可调 samples）。
  - 文档：补全 Pixiv 字段映射与随机策略说明，更新 API 契约（新增参数/返回字段）。
- Out:
  - 不做 ML 推荐/embedding/图像审美模型。
  - 不引入 Redis/消息队列/搜索引擎。
  - 不实现跨用户个性化（只有全局策略）。

## Risks / Notes
- 冷启动数据不足：若大量图片缺失热度字段，质量策略将退化为“随机里挑最不差”；需配合 backfill 提升覆盖率。
- 性能：Tournament Selection 会额外执行 `N-1` 次随机挑选（通常 `N=3..7`）；需限制上限并提供配置。
- 可解释性：必须在 JSON debug 暴露“评分/候选数量/策略来源”，避免“看起来不随机”的误解。
